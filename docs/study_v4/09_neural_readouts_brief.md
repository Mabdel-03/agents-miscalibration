# Neural dynamics readouts for study_v4 — implementation brief (added Sat 2026-09-05 21:15 EDT)

Goal: record the spec §8 internal-state readouts that vLLM cannot expose, WITHOUT touching the frozen generation pipeline. Two facts make this possible: (1) every request record in `<run_root>/requests/` stores the exact `prompt_token_ids` and completion `token_ids`; (2) spec §8.4 permits "a measurement-only exact-prefix teacher-forced replay" for capture. So a separate HF-transformers engine re-runs prefill over stored token sequences and reads residual-stream vectors at structural anchors.

## What is recorded (three readouts, in priority order)

### R1 — FINAL_HANDOFF_REPORT readout (family G primary; also the C reader state) — spec §8.7, §8.8, §9.2
For each C/G item (first 300 main items by rank: 150 HLE + 150 BCB, i.e. the N/D/M-panel prefix) and each of IND_VOTE, DEC, CEN_FLAT at N=5/B4 on the 32B flagship (CEN_RLM if it ever runs):
1. Compile the report AFTER `SELECTIONS.json` seals and BEFORE any correctness join: complete task, selected complete candidate (or the failure sentinel + missing-confidence flag), its explicitly personal confidence, decision rule + vote metadata (counts, ties, grouping_mode), known budget/call/role counts, then ≤4 non-selected candidates as §4.3 2,048-token packets in HMAC order, total evidence ≤ 8,192 rendered tokens validated on the complete render (§8.7). Same compiler feeds the tier-2b shadow forecast (`prompts/templates/forecast.txt` + trusted scope manifest {PERSONAL_FINAL, TEAM_SELECTED}; q_child_contract/q_recover/q_preserve null; operation_id NONE).
2. Render the reader prompt exactly as the shadow-forecast request would see it (same bytes, thinking off) and capture `h` at the **state anchor** = last prefill token before generation, at blocks `floor(f·(L−1))` for f ∈ {0.25, 0.5, 0.75} (Qwen3-32B: L=64 → blocks 15, 31, 47), plus the task-only anchor (last token of the task span, before any state). Store the four vectors (bf16→fp16, 5,120-d) per report.
3. Predictor (dev-only): on the 60 dev items × 3 architectures, five source-grouped outer folds × five inner folds; features = observables (architecture, domain, format, selected personal confidence + missing flag, vote count/ties/singleton, calls by role, slack, stop reason, prompt/candidate lengths) + full-report text embedding (pinned sentence-transformers model from `asys_env` if cached, else TF-IDF-SVD-64, recorded) vs the same + `h` PCA projections (ranks {16,32,64,128} clipped) and norm stats; logistic regression with penalties {0.1,1,10,100,1000}, one-SE rule; select site among the three blocks by inner loss preferring shallower within one SE; refit on all dev; freeze hashes. Confirmation: paired per-item Brier (baseline − augmented), 20,000 source-cluster bootstrap within superdomain, one-sided. Caveat recorded: 60 dev items make G estimation-oriented.

### R2 — native within-call temporal geometry (secondary; spec §8.4 "matched native prefill" + "within-call temporal trace")
For the same 300 items and the four flagship N=5/B4 policies, one episode each: select one call per declared role/phase by an outcome-blind hash (roles INDEPENDENT_SOLVER [IND root], DECENTRALIZED_MEMBER [DEC root / revision], CENTRAL_HUB, CENTRAL_WORKER; phases ROOT / COORDINATION / TERMINAL as applicable; ≤18 calls per item). For each selected call, teacher-force the stored `prompt_token_ids + completion token_ids[:k]` and capture the residual at: NATIVE_PREFILL (last prompt token), GENERATED_32, GENERATED_128, GENERATED_512 (the k-th generated token, only if k ≤ completion length, else `NOT_REACHED`), and FINAL_OBJECT_CLOSE (the token containing the closing brace of the parsed candidate JSON, located by byte offset → token offset via the tokenizer's decode boundaries; `JSON_CLOSE_MISSING` if the candidate is invalid; `FINAL_OBJECT_NOT_APPLICABLE` for subtask-result roles). One frozen block for confirmation (the R1-selected predictive block); development may store all three. Missing anchors never produce zero vectors.

### R3 — geometry & functional-diversity metrics (spec §8.5, §5.7)
From R2 vectors (and from IND/DEC terminal states): for each item/config with s comparable role states (IND: 5 roots; DEC: 5 terminal members; CEN_FLAT: hub + up to 4 workers, reported separately as different roles), compute raw norms, raw pairwise distances, mean pairwise cosine distance on centered/dev-standardized and unit-normalized versions, covariance eigenvalues, participation ratio, entropy effective rank, with the rank ceiling min(d_eff, s−1) printed beside every estimate; fixed s = 5 (or the minimum guaranteed by the role contract), 100 hash-determined subsamples when more states exist; 64-d dev-fitted PCA per checkpoint (fit inside training folds for prediction; separate frozen display transform). Alongside: scoped answer agreement, duplicate frequency, any-correct coverage, selected utility — and the association between geometry and those outcomes (descriptive; "predicts useful complementary outcomes beyond membership/budget/role/confidence/agreement/text" is the G-style test, not a causal claim).

## Explicitly NOT done in this run (recorded as amendments)
Activation edits / donors / specificity controls (family M), Patchscopes decoder, content-unit annotation panel, RLM controller/heap readouts, cross-checkpoint coordinate comparisons (each checkpoint gets its own fitted maps; dense-panel capture only if GPUs are free after the flagship panel).

## Engine and resources
- Engine: HF `transformers` 5.9 + torch 2.11+cu130 from `serve_env` (GPU torch), `AutoModelForCausalLM.from_pretrained(<HF snapshot path>, torch_dtype=bfloat16, device_map=…)` across **2 A100-80GB** for Qwen3-32B (≈62 GiB weights); forward hooks on `model.layers[b]` outputs (residual stream AFTER block b, i.e. the input to block b+1 — document the convention and the pre/post-norm choice); prefill only (`use_cache=False`, no generation), sequences batched by length; capture positions read from the hidden state at the anchor token index. Store fp16 vectors in chunked `.npz`/parquet files keyed by (request_id | report_id, block, anchor) under `<run_root>/neural/`, with an `ActivationRow` metadata jsonl per spec §8.13 (StateSnapshot_id, consumer_revision, condition, child_slot, nonce_hash, block, anchor_kind, structural_span, token_offset, channel, generated_token_count, missingness, tensor_hash, measurement_cost, operationally_available_at_checkpoint). Never store full attention maps or all tokens.
- Fidelity test (spec §10.5 "hook no-op parity"): teacher-forced replay of 20 stored completions → next-token argmax agreement with the stored sampled tokens and mean log-prob of the stored tokens; record max/mean logit discrepancy vs a second forward pass; exact token identity is asserted (tokenizer decode of stored ids == stored text).
- Compute: R1 ≈ 1,200 reports × ≤12k tokens ≈ 10M tokens; R2 ≈ ≤5,400 calls × ≤12k tokens ≈ 40M tokens; HF prefill on 2 A100 ≈ 3–5k tok/s → ~4 h total. Run as Slurm jobs with `--gres=gpu:a100:2` on `pi_manoli` (retire one 32B replica there when tier-1 generation drains) or opportunistically on `ou_bcs_low` (resumable chunks). Test the engine now on the one free GPU of node3904 with Qwen3-8B/14B.
- Environment isolation: capture jobs read `<run_root>/requests` and the sealed selections; they never read `data/protected`; correctness joins only in `aggregate`.
