## Spec essentials to preserve (do not reinvent; cite section)
- Candidate JSON schema (§3.5): {approach, evidence[{claim,support,uncertainty}], alternatives_considered[], failure_checks[], final_answer, confidence}; strict parse; one fence strip only; invalid → ineligible & scored 0; sentinel `{"status":"unavailable","failure_code":"NO_VALID_PARENT"}` for revisions.
- Seeds (§3.6): semantic seed = first 128 bits of HMAC-SHA256(study_seed, JCS([source_id, split, model_cell, episode_rep, actor_slot, purpose, step_slot, namespace])); request_id = SHA256(JCS([...])). Stateless banks: actor_slot=0, step_slot=draw ordinal.
- Framing 2×2 (§5.5, handoff prompts/framing_clauses.json): TEAM_1 / VOTE_1 literal clauses + selector description; R_bank=10 per cell; prefixes 1,2,3,5,9; pass@K K∈{1,2,3,5,10} unbiased estimator (metrics_reference.pass_at_k).
- Policies (§4.2): S_FRESH, S_HISTORY, IND_VOTE (11 framing at N=5; blind round-robin fresh epochs), DEC (≤8 rounds, N*(1+r)≤64, packets from previous round only, VOTE over latest slots), CEN_FLAT (coordinator_action: final|delegate ≤N−1 unique slots; ≤8 cycles; workers return subtask_result), CEN_RLM (D2/L5). 64 solver calls/episode + ≤64 selector calls.
- Packets (§4.3): 2,048 recipient tokens per peer packet; final-answer excerpt ≤1,024 (marked partial); priority order final_answer→evidence→failure_checks→alternatives→approach→confidence; exact excerpts, anonymous slot, candidate hash, truncation flags. Prompt envelope 32,768 in / 8,192 out; task envelope 4,096.
- Selectors (§4.4/§5.3): VOTE = plurality preserving multiplicity; MC by letter; exact-answer via outcome-blind normalization frozen on dev; code = public behavioral signature (needs a task-only public probe suite + 2 reviewers → NOT feasible in 42 h) → AMENDMENT S1: primary code vote uses the spec's declared fallback (Python AST canonicalization then exact source), grouping mode recorded. JUDGE_BEST = pointwise judge, 1,024-token cap, thinking off, one frozen judge model (use Qwen3-32B thinking-off), blind tie via HMAC.
- Budget (§6.5): FLOP oracle F_m(L,T) = prefill + Σ decode (multiply-add = 2 FLOPs) with analytic dense count (embeddings/vocab proj, attention, FFN); B0 = max over mandatory N=5 methods of the minimal-path full-cap reservation; B1/B2/B4/B8; reserve-before-launch, debit-actual, keep final-answer reserve; report slack + stop reason. Realized cost ≪ reservation so B4 will typically bind at the 64-call cap; B8 may alias B4 exactly (record).
- Evaluation (§3.3): HLE MC exact; HLE exact-answer via frozen judge + audit; BCB via official tests in fresh sandbox; protected labels joined only after selection seals. Failure rule: invalid/missing = incorrect, item stays in denominator.
- Stats (§9): six families A/O/R/C/G/M Holm; unexecuted family p=1; 20,000 source-cluster bootstrap; equal HLE/code weights.

## Cell design (proposal to be critiqued)
A cell = one (module, method, checkpoint, N, B, framing, episode_rep, item_shard) with ~10–20 items; CPU array task (1 CPU/4 G, 12 h); runs items sequentially with per-item concurrency = N slots (ThreadPool) against one endpoint chosen by shard round-robin; resumable per item (write `items/<source_id>.json` atomically; `meta.json` last). Framing-bank cells (F) write candidate banks; A-cells alias F banks by request_id lookup (read-only) before generating. Judging/evaluation are separate cell types run after pools seal: `judge_hle` (32B thinking-off), `eval_bcb` (apptainer), `judge_best` (32B thinking-off, 1,024 cap). Item order within each module = salted-hash rank so partial completion is a balanced prefix.
