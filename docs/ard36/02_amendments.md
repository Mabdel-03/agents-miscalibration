# ARD36 amendment register

Every deviation from `Agents_Round_Dynamics_36h_Spec.md`, each naming the claim it makes
unsupported. Frozen into `<run_root>/freeze/amendments.json` before dispatch; mid-run additions
are timestamped and justified, never silent. This is the study_v4 discipline that made its final
report auditable.

## D. Implementation

| id | deviation | spec clause | claim it limits |
|---|---|---|---|
| I1 | The split budget is one chat request using vLLM's native `thinking_token_budget`, not two requests with an exact-token-prefix continuation. Verified: forcing is a logits boost, so the boundary token is genuinely sampled, `boundary_injected == (thinking_tokens == budget)` is exact, exact token ids are preserved trivially, and ≥256 final tokens always remain after a cap hit. | §6.2 line 232 | None. This is the "existing tested backend mechanism" the clause asks for. The two-phase path remains the documented fallback if the smoke fails. |
| I2 | `configs/model_contracts.v1.json` is unedited: it is sha256-pinned, its loader rejects any key set other than the ordered dense ladder, and both ARD36 profiles already resolve through it by model size to the pinned revisions. | §6.1 | None. |
| I3 | `study/types.py` `NAMESPACES`/`PURPOSES` are unextended; the ARD namespaces live in `ard/contract.py`. The whitelist is enforced in `study/policies/base.py::ctx.seed()`, which the ARD episode loop does not use. | §18 cache identity | None. |
| I4 | The no-gold firewall is absolute rather than per-function: no runtime import closure may reach `agents_scaling.benchmarks` at all. `ard/graders/_boxed.py` vendors the one pure extractor this cost, with a parity test against the original. | §18 line 693 | Strengthens the guarantee. The claim is code-level discipline plus a runtime scan, never filesystem isolation, since the HF dataset cache is world-readable. |
| I5 | `study/stats.py`, `study/selection/vote.py::vote()` and `study/packets.py`'s packet compiler are vendored or wrapped in `ard/` rather than imported, because each is welded to a frozen vocabulary that ARD36 changes. A regression test asserts the vendored statistics reproduce the original bit-for-bit on an (`hle`,`bcb`) fixture. | n/a (engineering) | None; the study package stays frozen and its 541 tests stay green. |
| I6 | **Two-phase report generation for cap-hit draws.** The pilot (128 root draws, 8B) gave 83.6% valid reports against the 95% gate. Diagnosis: vLLM forces `</think>` at the thinking budget by a logits boost, but the model does not switch into report mode — it continues its derivation and spends all 256 report tokens on reasoning, emitting no tag at all (0 of 17 truncated draws contained even an opening `<final>`). A prompt-wording repair was tried first and **failed**, moving validity by under one point, because a model mid-derivation does not attend to the instruction. The remedy is the contingency the plan already documented: when and only when phase 1 hits the thinking cap, the report is generated as a `/v1/completions` continuation from the exact phase-1 token prefix through `</think>`, with the `<final>` opening prefilled so the answer comes first. The trigger is `boundary_injected` alone — uniform over every cap-hit draw, never conditioned on what phase 1 produced. Both physical requests are recorded and their FLOPs summed. | §6.2 line 232 (the split budget uses the existing tested backend mechanism; "Preserve exact token IDs across the continuation"; "Count both physical requests and any repeated prefill in runtime cost"), §6.3 lines 250-252 | This is the more faithful reading of §6.2's *independent* 256-token final allowance: under a forced boundary the genuinely independent report is the continuation, not the tail of an interrupted reasoning stream. The allowances stay 1,024 + 256 and the cap-hit rate remains a reported outcome. What it does limit: a cap-hit report is written from a prefilled opening tag, so its *format* is induced rather than spontaneous, and report-format compliance must not be reported as a model property for those draws. |
| I7 | **A report span cut by `max_tokens` after `</final>` closed still delivers its answer** (new `ParseStatus.TRUNCATED_AFTER_FINAL`, admitted to `VALID_PARSE_STATUSES`). The parser previously ranked the `truncated` status *above* the `<final>` checks, so any cut span was invalid even when a well-formed `<final>...</final>` had closed before the cut. Spec §6.3 conditions validity on the `<final>` tag alone ("missing/malformed `<final>` = invalid"), so the implementation was stricter than the contract it implements. Found by the two-phase pilot (128 root draws, 8B, train-split items only, pre-freeze): the continuation writes the answer immediately from the prefilled tag (`8</final>`, `0.0996</final>`) and then keeps reasoning inside `<evidence>`, exhausting the 256-token report allowance without closing it. All 16 such draws had committed a closed, non-empty answer. Measured effect on that pilot: validity 0.875 -> 1.000 with 0 of 67 cap-hit draws left undelivered. | §6.3 lines 250-252 (the report schema and its validity rule) | The answer channel is unaffected -- these reports commit before the cut. What it does limit is the *confidence* axis: a cut tail loses `<confidence>` (and `<evidence>`), so these draws carry a missing confidence under the frozen missing-is-missing policy, never an imputed 0.5. That missingness is **not random** -- it lands only on cap-hit draws, i.e. the longer, harder items -- so every calibration and confidence panel reports `conf_missing_rate` beside its estimate, the matched-n rule (plan §5.8) governs any cross-round or cross-protocol comparison, and confidence-conditioned controller features carry their existing missing-indicator. On this pilot that is 12.5% of decisions. Report-format compliance is already excluded as a model property for cap-hit draws under I6. |
