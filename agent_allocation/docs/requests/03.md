# Requests from agent 03 (protocols, prompts, policy ancestry)

Nothing here blocks agent 03; each item names what is needed for integration and what agent 03 does meanwhile.

## R03-1: a RunPaths entry and failure policy for context-limit events
`prompts.render` raises `ContextLimitEvent` when a VALID candidate's `<final>` element (plus the omission marker)
cannot fit `PACKET_ENVELOPE_CHARS` (12,000). `event.record` is a dict (`event`, `receiver_node_id`,
`source_node_id`, `final_chars`, `visible_chars`, `envelope_chars`). Under R4, agent 03 cannot choose where it is
written. **Asked:** a path such as `paths.context_limit_events` (`state/context_limit_events.jsonl`) and the
prespecified failure policy, e.g. "the receiver becomes terminal with no API call and counts as a context-limit
failure; no summarizer". At main A the envelope covers a whole code completion, so this should not happen.

## R03-2: a RunPaths entry for per-node render reports (optional)
`render_messages_with_report` returns an audit dict: packet availability, trim counts (characters and UTF-8 bytes
removed), blind display order, rendered character counts, and `messages_sha256`. That hash is audit data only,
never a cache key. **Asked:** decide whether to persist these. If so, provide a path, e.g.
`prompt_reports/{shard}/{node_id}.json`.

## R03-3: call the two validators the builder cannot call itself
`build_item_graph` has no config or endpoint lock in its frozen signature. **Asked:** from `plan`/`validate-config`
and before admission, call:
- `protocols.grid.check_config_constants(cfg)`. CP (team 4, from PEER round 1, 3 private steps) and POOLED
  (4 roots) are builder constants because `GridSpec` carries only `extension: bool`. This check reads
  `protocols.cp_*`, `pooled_synthesis_team_size`, `communication_mode` and `context_policy` (R9).
- `protocols.grid.check_budgets(graph, max_completion_tokens=lock.max_completion_tokens,
  requested_reasoning_max=cfg["reasoning"]["requested_reasoning_max"])`, per §5.5 (validate, never clip).

## R03-4: prompt lock at freeze
`prompts.render.prompt_lock_record()` returns `{prompt_version, templates: {file: sha256}, packet_envelope_chars}`.
**Asked:** write it to `paths.prompt_lock` at freeze and call `verify_prompt_lock(record)` on resume. The contract
formula keeps the envelope out of `prompt_version`, so changing the envelope does not change node identity. The
lock record is what catches that. Fold it into the version only if you want identity to change as well (that is a
contract change).

## R03-5: confirm the selector names in checkpoints (agent 06)
Every checkpoint carries `selector_name` = `"plurality"` (math500, mmlu_pro, bbh_logic4) or `"public_tests_only"`
(mbpp_plus), mirroring config `benchmarks[].selector`, plus `selector_version = "v1"`, in both views. Single-candidate
pools (`private_single/*`, `deep/*`, `pooled/4`) use the same name; 06 reports `SINGLE_CANDIDATE`. **Asked:**
confirm, or give the exact name and version strings 06 dispatches on (ideally as constants in `contracts.py`).

## Notes (no action unless you disagree)
- Templates are read from `paths.PROJECT_ROOT / "prompts"`, the pack files pinned by `CHECKSUMS.json`. This is the
  same in-tree/editable-install assumption `paths.PROJECT_ROOT` already makes. A wheel install would need
  `prompts/` as package data.
- The renderer refuses a spec whose `prompt_version` differs from `prompt_version()`, or whose
  `input_manifest_hash` differs from `public_task_hash(task)`. Graphs for dispatch must use
  `prompt_version=prompts.render.prompt_version()`.
- Build exactly one of `main` / `main_extension` per item. `main_extension` contains `main` with identical node ids
  and policy ids, so building both duplicates policy ids.
- `deep/1` (= root[0]) is emitted only for grids with a deep curve (main, high, replication), not the pilot grids.
  The pilot's DEEP 16A calls and A=4,096 roots stay with the lead.
- POOLED shows its four roots in a blind permutation (namespace `pooled_order_v1`, same hash inputs as PEER:
  seed, item, n=4, round 0, receiver slot 0), not slot order.
- `GenerationSpec.node_id` re-hashes the whole spec on every access (about 12 µs). Cache ids when iterating large
  graphs; `policy_cost` keeps a per-graph index for this reason.
