# Requests and notes from agent 04 (text benchmarks)

## 04-R1 — `PrivateEvalSpec.allowed_choices` (contract field)

**Need.** Grading must accept `A` / `(A)` only when the letter is a legal option *for that item* (MMLU-Pro items
have 3–10 options; BBH choice tasks 4 or 7). `grade_text(candidate, private)` receives no `PublicTask`, and
`PrivateEvalSpec` carries no option list, so the grader cannot tell a legal wrong letter (`GRADED`, False) from an
illegal one (`INVALID_OUTPUT`, unknown semantics).

**Minimal change.** Append to `PrivateEvalSpec`:

```python
    allowed_choices: tuple[str, ...] = ()   # legal final identities for option/boolean items; () for MATH/code
```

A trailing default keeps every existing constructor call (agent 05's code specs) valid; `load_record` already
coerces `tuple[str, ...]`. The frozen-hash test changes with it.

**Shim until then.** `grade_text(candidate, private, *, allowed_choices=None, timeout_s=5.0)` (keyword-only,
optional; positional frozen signature unchanged) reads `allowed_choices` from the keyword, else from
`private.allowed_choices` if the field exists. With neither, an option final is checked only as a single letter
`A`–`Z` (`detail_code="option_exact_unchecked"`). The grade worker (agent 05) can pass
`allowed_choices=task.allowed_choices` from the public manifest today. Once the field lands, the adapters fill it
(the hashed private record already contains it) and the keyword becomes redundant.

## 04-D1 — decision for the lead to confirm: MMLU-Pro duplicate question stems

The pinned MMLU-Pro test split has 357 groups of rows with an identical (outer-trimmed) question text: 391 extra
rows, mostly one source MMLU question with regenerated distractor sets (median option overlap between variants
is 100%). Left in, a panel could hold two variants of one question (dev vs main, or twice in main), which breaks
source-item disjointness and double-counts an item cluster.

Implemented rule (`mmlu_pro.apply_source_item_rule`, documented in the module docstring): among a group's rows
without a per-row exclusion, the lowest `question_id` stays eligible; every other row is an engineering exclusion
`duplicate_question_stem:mmlu_pro/<kept id>`. Outcome-blind, pre-generation, deterministic, and the same rule the
lab's ARD36 builder used. Eligible MMLU-Pro: 11,640 of 12,032 (391 duplicate stems + `mmlu_pro/8584`
`duplicate_option_text:A,D`). Most affected categories: law −142, health −135, biology −83. Reverting is a one-line
change in `load_inventory` if you prefer the raw inventory.

## 04-N1 — integration notes (no change requested)

- `benchmarks.<name>.source_record()` gives dataset-lock facts (repo, revision/commit, file, sha256, rows,
  licence, preprocessing version). All three sources are MIT.
- `benchmarks.text_manifest.exclusion_records(inventory)` is the engineering exclusion audit for
  `paths.exclusions`; `panel_audit(inventory, draw)` gives population and per-panel stratum counts.
- Panel sizes for `balanced150`: `n_dev = panels.pilot_items // 4 = 8`, `n_main = panels.main_items // 4 = 100`,
  `n_reserve = 8`; seed `cfg["seed"]`. `select_panels` raises on an empty or too-small eligible inventory.
- `bbh_logic4.load_inventory` copies the four pinned files plus `MANIFEST.json` into `paths.bbh_sources_dir`
  (write-once, verified against sha256 pins) and creates `paths.private_dir` with mode 0700 if needed. The shared
  cache is `/orcd/data/tpoggio/001/mabdel03/.cache/agent_allocation/bbh/<commit>/` (override
  `ALLOCATION_BBH_CACHE`); `bbh_logic4.fetch_sources()` refetches from GitHub with hash checks.
- MMLU-Pro prompt layout (`mmlu_pro-prompt-v1`): `<question>\n\nOptions:\nA. <opt>\nB. <opt>...`, question and
  options stripped of outer ASCII whitespace only.
- Time bounds: `grade_text` (MATH) and `math_equivalent` run in-process under one SIGALRM limit on a main thread
  (e.g. a process-pool worker). Called from any other thread they delegate to one persistent spawn child process
  per parent, which is hard-killed after `timeout_s + 10 s`; outages and timeouts become unknowns
  (`EVALUATOR_ERROR` / `None`), never False.
- For agent 06: `grading.text.normalize.option_identity(final, allowed_choices)` and `boolean_identity(final)` are
  the gold-blind identities the grader uses; building MMLU/BBH vote classes from them keeps selection and grading
  consistent. `math_equivalent` is strict (both directions), so an unparseable final is `None`, not a merge.
- Typed mock data: `text_manifest.fixture_inventory(benchmark)` returns 24 synthetic items built through the real
  adapters (`source_revision="synthetic-fixture-v1"`), drawable with `n_dev=4, n_main=8, n_reserve=4`.
