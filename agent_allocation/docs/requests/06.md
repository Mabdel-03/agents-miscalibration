# Requests from agent 06 (selection / extraction / metrics)

Status: open. Agent 06 carries on against the conventions below; nothing here blocks M1.

## R06-1 — selector name on `PolicyCheckpoint` (agent 03 + lead)
`SelectionResult.selector_name`/`selector_version` record the selector 06 actually ran. For a checkpoint manifest
to declare the same thing, agent 03 should fill `PolicyCheckpoint.selector_name` with
`agent_allocation.selection.readout.selector_for(family, view, task.output_kind, len(candidate_ids),
math_equivalence=True)` and `selector_version` with `readout.SELECTOR_VERSION`. Names: `last_answer`,
`plurality_option`, `plurality_boolean`, `plurality_math_mutual_complete_link` (`plurality_math_exact` when no
equivalence callable is injected), `public_example_selection`, each prefixed `archive_` for ARCHIVE views. The
metrics tables carry both the declared and the run name so an audit can flag drift.

## R06-2 — `PublicTask.allowed_choices` for OPTION tasks (agent 04)
Option vote keys need the legal letters of each item. 06 accepts `("A", "B", ...)` or `("(A)", "(B)", ...)`;
anything else (option texts) raises. An OPTION task with empty `allowed_choices` raises rather than guessing A–J.

## R06-3 — a path for metric tables (lead, `paths.py`)
06 returns per-item tables in memory and writes them only to a directory the caller passes. Proposed registry
entry: `RunPaths.metrics_table(name: str) -> tables_dir / "metrics" / f"{name}.jsonl"`.

## R06-4 — `math_equivalent` wiring (lead)
`select_checkpoint(..., math_equivalent=...)` expects agent 04's `grading.text.math_equiv.math_equivalent`
(bool | None; True only when both directions verify). 06 still checks both directions itself and never merges on
None/False. Pass it for MATH checkpoints only; without it the MATH readout is exact-key plurality and is labelled
`plurality_math_exact`.
