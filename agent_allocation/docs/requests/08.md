# Requests from agent 08 (QA) to the lead

Each defect below has a strict-xfail test in `tests/integration/test_lead_contract_defects.py` or

## Defects in lead-owned files

### D1. `ERROR_ENVELOPE` has no declared policy (contracts.py:121-133)
`TransportStatus.ERROR_ENVELOPE` is in neither `RETRYABLE_TRANSPORT` nor `CIRCUIT_BREAKING_TRANSPORT`.
**What goes wrong:** OpenRouter returns HTTP 200 with `{"error": {"code": 502|429, ...}}` when the upstream provider
fails. Agent 02 has to guess. If it treats "not in either set" as terminal, a brief upstream problem permanently
removes a node from the paired grid, and every descendant, with no retry. If it releases the reservation, money
that may have been billed is freed.
**Fix:** put `ERROR_ENVELOPE` in `RETRYABLE_TRANSPORT`, or map it by `error.code` in agent 01's classifier to
`RATE_LIMITED`/`UPSTREAM_ERROR`/`BAD_REQUEST`. Either way, state whether its reservation is settled from `usage`
(if present) or charged at the maximum.
Test: `test_s15_10_every_non_ok_transport_status_has_a_declared_policy`.

### D2. The ledger journal cannot rebuild the unresolved/in-flight split (contracts.py:165-171)
`LedgerEventKind` has RESERVE/SENT/SETTLE/RELEASE_UNSENT/CHARGE_MAX/RECONCILE, but nothing marks an attempt as
*unresolved* (ambiguous timeout, awaiting reconciliation). `LedgerSnapshot` has separate `in_flight` and
`unresolved` fields, and the $2 pause (`max_unresolved_usd`) reads `unresolved`.
**What goes wrong:** after a restart, a journal replay sees SENT reservations without a terminal event and cannot
tell "timed out, maybe billed" from "was in flight when the process died". If replay counts them as `in_flight`,
the $2 circuit breaker reads 0 after a crash with $5 of ambiguous exposure outstanding.
**Fix (minimal):** add `LedgerEventKind.UNRESOLVED` (amount 0) and define on replay that every SENT reservation
without a terminal event counts as unresolved.
Test: `test_d2_ledger_journal_can_mark_an_attempt_unresolved`.

### D3. `GradeResult` accepts contradictory tri-state records (contracts.py:478-488)
`GradeResult(status=EVALUATOR_ERROR, semantic_correct=False)` and `GradeResult(status=GRADED, semantic_correct=None)`
both construct and round-trip. That is exactly ARD36's tri-state grading error, allowed by the type.
**Fix:** `__post_init__`: `GRADED` requires a bool; `EVALUATOR_ERROR`/`NOT_EVALUATED` require `None`;
`INVALID_OUTPUT` requires `operational_success is False`.
Test: `test_s15_14_grade_result_rejects_inconsistent_tri_state`.

### D4. `PublicCheckResult.pass_fraction` turns "no public case" into 0.0 (contracts.py:461-463)
**What goes wrong:** if an MBPP+ prompt's `assert` fails to parse, `cases_total == 0`. Every candidate then scores
0.0 and the public-example selector quietly becomes a pure random-priority pick instead of pausing. That breaks R9
and spec 11.2 ("a public-check infrastructure error pauses this selector").
**Fix:** return `None` when `cases_total == 0`, and have `run_public_checks` report `INFRASTRUCTURE_ERROR` there.
Test: `test_d4_pass_fraction_with_zero_public_cases_is_not_zero`.

### D5. Node-local SQLite path collides across run dirs (paths.py:31-36, 52-53)
`default_local_state_dir(chosen.name)` gives `/scratch/$USER/agent_allocation/<basename>/state.sqlite`.
**What goes wrong:** every test that uses `RunPaths.for_run(tmp_path / "run")` without `local_state_dir` shares
`/scratch/mabdel03/agent_allocation/run/state.sqlite`. So do all eight agents' worktrees running their default
`artifacts/openrouter_agent_allocation_v1`, and the real run on the same node. Parallel test runs corrupt each
other, and `StateStore.recover` can restore another run's state. Checked on node4004:
`RunPaths.for_run("/tmp/x1/run").state_db_local == RunPaths.for_run("/tmp/x2/run").state_db_local`.
**Fix:** key the local dir by a hash of the resolved run dir, e.g. `f"{name}-{sha256(str(run_dir.resolve()))[:12]}"`,
and record the run dir inside the SQLite file so it can be checked when the file is opened.
Test: `test_d5_distinct_run_dirs_never_share_local_sqlite`.

### D6. Sibling run dirs share write-once locks (paths.py:51)
`locks_dir` defaults to `run_dir.parent / "locks"`.
**What goes wrong:** `allocation prepare-data --run-dir artifacts/mock_e2e` (or any smoke test) writes the
write-once `artifacts/locks/datasets.json` / `openrouter_endpoints.json` (possibly from `fake_endpoint_lock`). The
real run then reads the mock's lock and cannot replace it.
**Fix:** default locks to `run_dir / "locks"`, or refuse a lock whose recorded `run_dir` differs.
Test: `test_d6_sibling_run_dirs_do_not_share_write_once_locks`.

### D7. Declared config knobs are never read or validated (config.py:24-56, 91-122)
- a. `protocols.cp_team_size`, `cp_peer_rounds`, `cp_private_rounds` and `pooled_synthesis_team_size` are never
  read. The extension shape is hardcoded (`GridSpec.extension: bool`), so setting `cp_private_rounds = 2` changes
  nothing and raises no error.
- b. Deep budgets are not checked against `reasoning.requested_reasoning_max` (24,576). With
  `deep_high_multipliers = [2, 4, 8]`, the 32,768-token calls pass validation (spec 5.5: validate, never clip).
- c. `budget.reservation_multiplier = 0.5` and `max_unresolved_spend_usd = 50` pass validation.
**Fix:** read the CP/POOLED knobs into `GridSpec`, or require them to equal the hardcoded shape; validate
`A * max(multiplier) <= requested_reasoning_max`, `reservation_multiplier >= 1` and `max_unresolved_spend_usd <= 2`.
Tests: `test_d7_*`, `test_d7b_*`, `test_d7c_*`.

### D8. One selection seal per partition, but CP/POOLED live in MAIN (paths.py:125-126, contracts.py:90-91)
Gate 4 schedules CP/POOLED after the main forecast is trustworthy, and interim analysis joins grades before
collection ends. **What goes wrong:** once `selections/main.jsonl` is sealed and grades are joined, extension
selections for the same partition must either rewrite a sealed file after a grade join (breaking the seal
guarantee) or cannot be sealed at all.
**Fix:** seal per batch, `selections/{partition}/{batch}.jsonl` + seal, with an append-only chain
(`{sha256, count, sealed_at, previous_seal_sha256}`), and forbid rewriting an existing batch.
(Test pending on `selection.seal`; see AUDIT.md.)

### D9. Grade and public-check paths omit the evaluator version (paths.py:119-124)
`grades/{shard}/{candidate_id}.json` has no grader version or environment digest. **What goes wrong:** spec 16
allows repairing grades from stored outputs. A repaired grader overwrites the earlier verdict in place, so the
audit cannot show what changed, and a stale grade from the old evaluator looks current.
**Fix:** `grade(candidate_id, grader_version)` or a versioned subdirectory; readers select a version explicitly.

### D10. `SelectionResult.status` is a bare `str` (contracts.py:475)
The codec accepts any string (`"Selected "` loads fine), so status-based guards (abstention counting,
paused-selector blocking) can be bypassed by a typo. **Fix:** type it as `SelectionStatus`, or validate it in
`__post_init__`. Test: `test_d10_selection_status_is_validated_by_the_codec`.

### D11. `load_record` fills missing fields from defaults (contracts.py:593-605)
A `PolicyCheckpoint` written without `view` reloads as `CURRENT`. Missing `repetition_id` or `parent_ids` on a
`GenerationSpec` reload as `0`/`()` and produce a *different* `node_id` with no error. That is the writer/reader
drift the codec exists to prevent. **Fix:** a `strict=True` default that requires every field; keep an explicit
`strict=False` for fixtures. Test: `test_d11_load_record_refuses_missing_fields`.
