# Requests from agent 01 (OpenRouter adapter)

All three were resolved in contract v2 (`allocation-v1` c546b46, `docs/00_contract.md` §6). They stay here as a
record.

## R01-1: policy for `TransportStatus.ERROR_ENVELOPE` — RESOLVED (option b)

`ERROR_ENVELOPE` is in `RETRYABLE_TRANSPORT`. Its reservation is kept exactly as for `AMBIGUOUS_TIMEOUT`: settle from
generation metadata, or `charge_max`. The adapter still returns `ERROR_ENVELOPE` for any HTTP 2xx without exactly one
usable completion:

- a non-null top-level `error`;
- a choice-level `error`;
- a non-JSON body;
- zero or several choices;
- a choice without `message`.

`error_detail` includes the embedded `code=`. `tests/unit/api/test_classification.py` pins the v2 membership.

## R01-2: `contracts.Generator` signature — RESOLVED

The Protocol now matches `OpenRouterClient.generate(spec, messages, *, attempt_id, lock, sampling)`.

## R01-3: exact served-model and provider match — AGREED

`PROVIDER_MISMATCH` fires when the response's `provider` differs from `lock.provider_name`, or its `model` differs
from `lock.model`. Both comparisons are exact. The canary confirms the returned `model` string. Any alias becomes an
explicit, recorded lock amendment, never a looser check.

A tier change (`google-ai-studio` to `/flex` or `/priority`) cannot be seen in the response, because all three report
`"Google AI Studio"`. Only `/generation` `service_tier` shows it, so check it with
`api.reconcile.reconcile_generation` or `metadata_identity_problems`.
