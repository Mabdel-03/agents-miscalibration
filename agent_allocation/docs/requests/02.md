# Requests from agent 02 (scheduler, persistence, ledger)

## R02-1 — additive `result` key in raw artifacts (contract §2 "02" `write_raw_response`, §3)

`write_raw_response` writes the six listed keys **plus** `result` = `dump_record(outcome.result)` exactly as the
client classified it (raw pointer fields still `None`). Reason: the brief requires "crash after provider response
before DB commit" to recover with zero new requests. Without the classified result inside the fsync'd artifact,
recovery would have to re-classify raw HTTP bytes (agent 01's logic) or re-send. Please bless the additive key in
§3 (readers that only use the six keys are unaffected). No contract type changes.

## R02-2 — (informational) sentinels persist until cleared

`allocation stop --run-dir X [--drain]` writes `control/STOP` / `control/DRAIN`; the dispatcher refuses to start while
either exists (stop reason `control_sentinel_present`) so a requeued Slurm job cannot silently resume a stopped run.
`allocation stop --run-dir X --clear` removes them. If you prefer the dispatcher to consume sentinels, say so.
