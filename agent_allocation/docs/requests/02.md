## R02-3 — QA checker loses exposure on `LedgerEventKind.UNRESOLVED` (for agent 08)

`tests/integration/reference_impl.py::LedgerChecker.replay` has no branch for `UNRESOLVED`: the event falls through to
the terminal-event code, which subtracts the reservation from `open_sent` without setting `terminal`. Reproduction:

```python
tl = [RESERVE 0.5 a:1, SENT a:1, UNRESOLVED 0 a:1, RESERVE 0.6 b:1]   # ceiling 1.0
LedgerChecker(D("1.0")).replay(tl)  ->  violations [], exposure 0.6, open_sent 0.0   # should flag 1.1 > 1.0
```

Fix: treat `UNRESOLVED` as a state note (like `RECONCILE`, or keep the attempt in `open_sent`). The production
dispatcher writes `UNRESOLVED` for every ambiguous timeout / error envelope / unknown-cost exchange.

## R02-5 — (informational, contract §2 "02") semantics the lead may want to state in §6

* `SENT` is journaled with an urgent fsync *after* the HTTP limiter is acquired and stop/drain/circuit are re-checked,
  immediately before `client.generate`. `release_unsent` raises for any attempt marked sent (QA s15.08).
  CONNECT_FAILED (provably unsent) therefore settles at 0 instead of being released.
* `run(..., max_usd)` applies `max_usd` (and `budget.pilot_allowance_usd` for canary/pilot-only plans) through the
  additive `CollectionLedger.set_run_cap`, cleared when `run()` returns; `set_active_ceiling` stays the lead's
  provider-derived ceiling and the dispatcher never changes it.
* `RunSummary.stop_reason` ∈ `runtime.scheduler.STOP_REASONS` = {completed, budget_exhausted, circuit_open,
  stop_sentinel, drain, control_sentinel_present, stalled}; specifics in `stop_detail` / `circuit_reason`.
